# Spec Delta

## Purpose

为全应用提供跨端统一的 HTTP API 客户端基础设施：响应信封解析、错误归一化、会话认证与登录失效刷新、请求签名、脱敏日志与环境配置，使后续任何业务接口的接入只需声明请求与响应模型。

## ADDED Requirements

### Requirement: 统一响应信封与业务码校验

服务端响应 SHALL 按统一信封（`code` / `msg` / `data`）解析。`code == 200` MUST 视为业务成功并返回 `data`；`code != 200` MUST 转为携带业务码与服务端提示（`msg`）的业务异常。失败响应的 `data` 字段结构不稳定（可能为空数组、空对象或异常结构），解析过程 MUST NOT 因此报解析错误。

#### Scenario: 业务成功取数据

- **WHEN** 服务端返回 `code == 200` 且 `data` 携带业务数据
- **THEN** 调用方获得该业务数据，不产生异常

#### Scenario: 业务失败转业务异常

- **WHEN** 服务端返回 `code != 200`（如账号或密码不正确）
- **THEN** 调用方获得业务异常，异常携带该业务码与服务端 `msg` 文案

#### Scenario: 失败信封的异常 data 结构不致解析失败

- **WHEN** 服务端返回 `code != 200` 且 `data` 为空数组等非预期结构
- **THEN** 仍按业务失败处理并携带 `msg`，不产生解析类错误

### Requirement: 网络异常归一化

底层传输与解析失败 SHALL 归一化为有限的错误类别：HTTP 状态错误、请求超时、网络不可用、传输失败、响应解析失败。每个类别 MUST 携带固定的用户可展示中文文案，供上层直接呈现。

#### Scenario: 请求超时

- **WHEN** 请求在超时时间内未完成
- **THEN** 错误类别为请求超时，文案为超时提示

#### Scenario: 网络不可达

- **WHEN** 设备无网络或无法连接服务端
- **THEN** 错误类别为网络不可用，文案为不可用提示，且不产生无意义的后续重试

#### Scenario: 响应解析失败

- **WHEN** 响应体不是合法信封 JSON
- **THEN** 错误类别为响应解析失败，文案为解析失败提示

#### Scenario: HTTP 状态错误

- **WHEN** 服务端返回非 2xx 状态码（登录失效判定场景除外）
- **THEN** 错误类别为 HTTP 状态错误，文案包含状态码信息

### Requirement: 认证注入与登录失效刷新

携带会话令牌的请求 SHALL 注入 `Authorization: Bearer <token>` 头及公共请求头（平台标识、应用版本、设备标识、语言等）。收到登录失效信号（HTTP 401，或 2xx 但业务码为 401）时 SHALL 使用刷新令牌发起令牌刷新，并在成功后重试原请求一次；刷新失败 MUST 清除本地会话令牌并发出「登录已失效」事件。登录请求、刷新请求以及携带 `X-Skip-Auth-Refresh: true` 头的请求 MUST NOT 触发刷新流程。

#### Scenario: 携带令牌的请求注入认证头

- **WHEN** 本地存有会话令牌且发起业务请求
- **THEN** 请求携带 `Authorization: Bearer` 头与全部公共请求头

#### Scenario: 登录失效后刷新令牌并重试成功

- **WHEN** 业务请求收到 401 且刷新令牌可用
- **THEN** 系统刷新令牌成功并重试原请求一次，调用方得到原请求的正常结果

#### Scenario: 刷新失败清除会话

- **WHEN** 令牌刷新请求失败或重试后仍为 401
- **THEN** 本地会话令牌被清除，且发出一次「登录已失效」事件

#### Scenario: 登录请求不触发刷新

- **WHEN** 登录请求自身失败或返回 401
- **THEN** 不进入刷新流程，按原始错误返回

### Requirement: 请求签名

除免签路径（登录）外，请求 SHALL 附带时间戳、随机串与签名头，签名计算规则与原工程一致（密钥 + 时间戳 + 随机串 + 规范化参数 + 密钥 的摘要值，大写十六进制；规范化参数按参数名字典序拼接并剔除签名相关字段、文件字段与空值）。签名密钥 MUST NOT 提交进版本库。启用响应验签时，验签失败 MUST 使请求按传输错误失败。

#### Scenario: 登录请求免签

- **WHEN** 发起登录请求
- **THEN** 请求不附带签名头，正常完成

#### Scenario: 业务请求携带签名

- **WHEN** 发起非免签路径的业务请求
- **THEN** 请求携带时间戳、随机串与签名头，且服务端验签通过（联调实证）

#### Scenario: 签名密钥缺失

- **WHEN** 构建配置未提供签名密钥
- **THEN** 签名关闭（不附带签名头）并在测试环境日志中显式告警，不导致崩溃

### Requirement: 请求日志与脱敏

测试环境 SHALL 输出请求与响应日志（方法、路径、头、体裁剪至 8KB）。日志中敏感字段（令牌、密码、签名等）MUST 以遮蔽形式呈现。非测试环境 MUST NOT 输出网络日志。

#### Scenario: 测试环境输出脱敏日志

- **WHEN** 测试环境发起登录请求
- **THEN** 日志包含请求信息，且密码与令牌字段为遮蔽形式

#### Scenario: 生产环境静默

- **WHEN** 生产环境发起任意请求
- **THEN** 不产生网络日志输出

### Requirement: 全局请求计数

系统 SHALL 维护进行中请求的全局计数状态供界面消费（任意请求数 > 0 即为忙碌）。携带跳过标记的请求 MUST NOT 计入。计数 MUST 随请求结束（无论成败）正确回落，不残留。

#### Scenario: 并发请求计数正确

- **WHEN** 两个请求并发进行且先后结束
- **THEN** 全局忙碌状态在全部结束前持续为真，全部结束后恢复为假

#### Scenario: 跳过标记的请求不计数

- **WHEN** 发起携带全局加载跳过标记的请求
- **THEN** 全局忙碌状态不因其改变

### Requirement: 环境配置

客户端 SHALL 支持 dev / uat / prod 三套服务端地址，取值与原工程一致，可在构建时选择。签名密钥与签名模式 SHALL 经构建配置注入，MUST NOT 提交进版本库。

#### Scenario: 指定环境的请求发往对应地址

- **WHEN** 以 uat 环境配置构建并发起登录请求
- **THEN** 请求发往 uat 服务端地址

#### Scenario: 密钥不入库

- **WHEN** 检查版本库中的源码与构建脚本
- **THEN** 找不到任何签名密钥取值，密钥仅存在于本地未入库配置
